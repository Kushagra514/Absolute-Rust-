# 7.5 — Separating Modules into Different Files

> **Mental Model**
>
> `mod` → module declare karta hai + Rust ko batata hai code kahan milega
>
> `use` → existing module/item ka shortcut banata hai
>
> File structure → module tree ko reflect karti hai

---

## 📁 Modules ko Separate Files mein Kyun Rakhein?

Jab modules bade ho jaate hain, unka code alag files mein move karna:

- code ko navigate karna easier banata hai
- files ko readable rakhta hai
- module structure ko clearly organize karta hai

> **Important:** Code ko different files mein move karne se module tree change nahi hota.

---

## 🌳 `front_of_house` ko Separate File mein Move Karna

Pehle `src/lib.rs` mein module inline tha:

```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}
```

Ab module ke andar ka code hata kar:

```rust
mod front_of_house;
```

likhenge.

### `src/lib.rs`

```rust
mod front_of_house;

pub use crate::front_of_house::hosting;

pub fn eat_at_restaurant() {
    hosting::add_to_waitlist();
}
```

> `mod front_of_house;` compiler ko batata hai ki `front_of_house` module exist karta hai aur uska code module declaration ke according file mein milega.

Ab file banani hogi:

```text
src/front_of_house.rs
```

### `src/front_of_house.rs`

```rust
pub mod hosting {
    pub fn add_to_waitlist() {}
}
```

Compiler `src/lib.rs` mein:

```rust
mod front_of_house;
```

dekhta hai, isliye `front_of_house.rs` mein module ka code dhundta hai.

---

## ⚠️ `mod` ≠ `include`

Bahut important distinction:

```rust
mod front_of_house;
```

**"file ko yahan paste/include karo"** nahi hai.

`mod` ka kaam:

```text
1. Module declare karo
2. Module tree mein uski position establish karo
3. Rust ko us module ka source code locate karne do
```

Ek module ko module tree mein **sirf ek baar** `mod` se declare/load karna hota hai.

Uske baad doosri files us module ke code ko `mod` se dobara load nahi karti.

Instead:

```text
path
use
```

ke through already-declared module ke items access karti hain.

> **`mod` = module declare karo**
>
> **`use` = existing module/item ko access karne ka shortcut banao**

---

## 🪜 Child Module ko Separate File mein Move Karna

Ab `hosting` bhi alag file mein move karte hain.

`hosting`, `front_of_house` ka **child module** hai.

Isliye uski file directly `src/` mein nahi hogi.

### Pehle

```text
src/
└── front_of_house.rs
```

`front_of_house.rs` mein:

```rust
pub mod hosting {
    pub fn add_to_waitlist() {}
}
```

### Ab Change

`front_of_house.rs` mein sirf declaration rahega:

```rust
pub mod hosting;
```

Ab directory structure:

```text
src/
├── lib.rs
├── front_of_house.rs
└── front_of_house/
    └── hosting.rs
```

### `src/front_of_house/hosting.rs`

```rust
pub fn add_to_waitlist() {}
```

---

## 🧠 File Location Module Tree ko Follow Karti Hai

Module tree:

```text
crate
└── front_of_house
    └── hosting
        └── add_to_waitlist
```

File structure:

```text
src/
├── front_of_house.rs
└── front_of_house/
    └── hosting.rs
```

Mapping:

```text
front_of_house
      ↓
src/front_of_house.rs

hosting
      ↓
src/front_of_house/hosting.rs
```

> **Child module ki file uske ancestors ke naam wale directory ke andar hoti hai.**

---

## ❌ `hosting.rs` ko `src/` mein Kyun Nahi Rakhen?

Agar:

```text
src/
├── front_of_house.rs
└── hosting.rs
```

rakho, toh Rust `hosting.rs` ko root module ka child samjhega.

Yaani expected structure:

```text
crate
├── front_of_house
└── hosting
```

But hume chahiye:

```text
crate
└── front_of_house
    └── hosting
```

Isliye `hosting.rs` ko:

```text
src/front_of_house/hosting.rs
```

mein rakhna padta hai.

> **Compiler ke file-location rules module tree ko filesystem structure ke saath match karte hain.**

---

## 🔄 Module Tree Same Rehta Hai

Files alag karne ke baad bhi module tree:

```text
crate
└── front_of_house
    └── hosting
        └── add_to_waitlist
```

hi rehta hai.

Isliye:

```rust
hosting::add_to_waitlist();
```

jaise existing function calls ko change karne ki zarurat nahi.

**Code alag files mein gaya hai, module relationship same hai.**

---

## 🔗 `use` Par Koi Effect Nahi

`src/lib.rs` mein:

```rust
pub use crate::front_of_house::hosting;
```

same reh sakta hai.

Why?

Because `use` ko farak nahi padta ki module ka code:

```text
same file mein hai
```

ya:

```text
separate file mein hai
```

`use` module tree ke path ke through item access karta hai.

```text
Files
  ↓
module structure establish hota hai

use
  ↓
existing module tree ke path ko access karta hai
```

> **`use` ye decide nahi karta ki kaunsi files compile hongi.**

---

# 📂 Complete Example

### File Structure

```text
src/
├── lib.rs
├── front_of_house.rs
└── front_of_house/
    └── hosting.rs
```

### `src/lib.rs`

```rust
mod front_of_house;

pub use crate::front_of_house::hosting;

pub fn eat_at_restaurant() {
    hosting::add_to_waitlist();
}
```

### `src/front_of_house.rs`

```rust
pub mod hosting;
```

### `src/front_of_house/hosting.rs`

```rust
pub fn add_to_waitlist() {}
```

Module tree:

```text
crate
└── front_of_house
    └── hosting
        └── add_to_waitlist
```

---

## 🕰️ Alternate File Paths

Rust modern/idiomatic path ke saath ek **older `mod.rs` style** bhi support karta hai.

### Root-level Module

For:

```rust
mod front_of_house;
```

Rust dono locations support karta hai:

```text
src/front_of_house.rs
```

or:

```text
src/front_of_house/mod.rs
```

### Child Module

For:

```rust
pub mod hosting;
```

inside `front_of_house`, Rust dono locations support karta hai:

```text
src/front_of_house/hosting.rs
```

or:

```text
src/front_of_house/hosting/mod.rs
```

---

## ⚠️ Same Module ke Liye Dono Styles Mat Use Karo

Agar same module ke liye dono exist karein:

```text
src/front_of_house.rs
```

and:

```text
src/front_of_house/mod.rs
```

toh compiler error dega.

```text
front_of_house
├── front_of_house.rs
└── front_of_house/mod.rs
```

❌ Same module ke liye dono styles allowed nahi hain.

---

## 🔀 Different Modules mein Styles Mix Kar Sakte Ho

Project ke different modules mein old aur new styles mix karna technically allowed hai.

Example:

```text
src/
├── front_of_house.rs
└── back_of_house/
    └── mod.rs
```

Ye possible hai.

Lekin:

> **Mixed styles project ko navigate karna confusing bana sakte hain.**

So consistency generally better hai.

---

## ⚠️ `mod.rs` Style ka Downside

Old style:

```text
src/front_of_house/mod.rs
src/back_of_house/mod.rs
src/orders/mod.rs
src/users/mod.rs
```

Large projects mein bahut saari files ka naam:

```text
mod.rs
```

ho sakta hai.

Editor mein multiple `mod.rs` files open hone par identify karna confusing ho sakta hai.

Isliye modern style:

```text
front_of_house.rs
back_of_house.rs
orders.rs
users.rs
```

zyada clear hoti hai.

---

# 🧠 Important Distinction

```text
mod
 ↓
Module declare karta hai
 ↓
Rust source file locate karta hai
```

```text
use
 ↓
Already existing module/item ko access karta hai
 ↓
Shortcut provide karta hai
```

> **`use` files ko compile nahi karta.**
>
> **`mod` module ko crate ke module tree ka part banata hai.**

---

## 🔥 Complete Mental Model

```text
                  CRATE
                    │
              mod declaration
                    ↓
             MODULE TREE
                    │
          ┌─────────┴─────────┐
          │                   │
    Inline module        Separate file
                              │
                     Rust conventional
                       location par
                       source dhundta hai
                              │
                              ↓
                         Module code
                              │
                              ↓
                       path / use se
                         access karo
```

### File ↔ Module Relationship

```text
mod front_of_house;
        ↓
src/front_of_house.rs
```

```text
pub mod hosting;
        ↓
src/front_of_house/hosting.rs
```

Alternative old style:

```text
mod front_of_house;
        ↓
src/front_of_house/mod.rs
```

```text
pub mod hosting;
        ↓
src/front_of_house/hosting/mod.rs
```

---

## 🧠 Final Cheat Sheet

| Syntax / Concept | Meaning |
|---|---|
| `mod front_of_house;` | `front_of_house` module declare karo |
| `src/front_of_house.rs` | Root-level module ka source |
| `src/front_of_house/hosting.rs` | `front_of_house` ke child `hosting` ka source |
| `mod.rs` | Older supported file style |
| `use` | Existing module/item ka shortcut |
| `pub use` | Public re-export |
| `mod` | Module ko module tree ka part banata hai |
| File separation | Code organization improve karta hai |
| Same module + both file styles | ❌ Compiler error |
| Different modules + mixed styles | ✅ Allowed, but confusing |
| `use` affects file compilation? | ❌ No |
| Module tree after splitting files | ✅ Same |

> **Golden Rule**
>
> `mod` tells Rust **"ye module exist karta hai aur iska code locate karo."**
>
> `use` tells Rust **"already existing module/item ko is scope mein shortcut se use karna hai."**
>
> Files alag karne se **module tree nahi badalta**, sirf code ki physical organization badalti hai.
