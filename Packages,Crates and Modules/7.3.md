# 7.3 — Paths for Referring to an Item in the Module Tree

> **Mental Model**
>
> `Path` = code ka address
>
> `Absolute Path` → crate root se start
>
> `Relative Path` → current module se start
>
> `pub` → path ko accessible banata hai

---

## 🔗 Paths

Rust mein kisi function, struct, enum, module etc. ko access karne ke liye uska **path** use karte hain.

Path mein identifiers `::` se separate hote hain:

```text
crate::front_of_house::hosting::add_to_waitlist
```

> **Path = module tree mein kisi item ka address.**

---

## 🛣️ Absolute vs Relative Path

Rust mein paths ke 2 forms hote hain:

| Path | Starts from |
|---|---|
| **Absolute** | Crate root |
| **Relative** | Current module |

### Absolute Path

Current crate ke liye `crate` se start hota hai:

```rust
crate::front_of_house::hosting::add_to_waitlist();
```

External crate ke liye crate ke naam se start hota hai:

```rust
some_crate::some_module::some_function();
```

### Relative Path

Current module se start hota hai:

```rust
front_of_house::hosting::add_to_waitlist();
```

Relative paths `self`, `super`, ya current module ke kisi identifier se start ho sakte hain.

---

## 🧩 Example

```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}

pub fn eat_at_restaurant() {

    // Absolute path
    crate::front_of_house::hosting::add_to_waitlist();

    // Relative path
    front_of_house::hosting::add_to_waitlist();
}
```

Dono paths same function tak pahunch rahe hain:

```text
crate
└── front_of_house
    └── hosting
        └── add_to_waitlist
```

Difference sirf starting point ka hai.

---

## 🔐 Privacy aur Paths

**Correct path hona enough nahi hai.**

Rust mein items **private by default** hote hain:

```rust
mod front_of_house {
    mod hosting {
        fn add_to_waitlist() {}
    }
}
```

Agar bahar se:

```rust
crate::front_of_house::hosting::add_to_waitlist();
```

access karne ki koshish karein, compiler error dega because `hosting` private hai.

> **Path correct ho sakta hai, phir bhi privacy rules ki wajah se access forbidden ho sakta hai.**

---

## ⚠️ `pub mod` Alone Is Not Enough

Agar:

```rust
mod front_of_house {
    pub mod hosting {
        fn add_to_waitlist() {}
    }
}
```

Toh `hosting` public hai.

Lekin `add_to_waitlist()` abhi bhi private hai.

Isliye ye bhi chahiye:

```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}
```

> **Module ko `pub` karna uske contents ko automatically public nahi karta.**

---

## 👀 Privacy Direction

### Parent → Child

Parent module **child ke private items access nahi kar sakta**.

```text
parent
   ↓
private child item ❌
```

### Child → Parent

Child module apne **ancestor/parent ke items access kar sakta hai**, including private ones.

```text
child
   ↓
ancestor item ✅
```

> **Child apne surrounding context ko dekh sakta hai, but parent child ke hidden implementation details ko nahi dekh sakta.**

---

## 📦 Why Privacy?

Private items ko implementation details ki tarah hide kar sakte hain.

```text
Internal implementation
        ↓
     private
        ↓
Bahar ka code depend nahi karta
        ↓
Implementation change karna easier
```

Public items tumhare crate ka **public API** banate hain.

> **Public API = woh interface jiske through doosre projects tumhari library ko use karte hain.**

---

## 🏗️ Library + Binary Package

Ek package mein dono ho sakte hain:

```text
src/
├── lib.rs
└── main.rs
```

Recommended organization:

```text
lib.rs
  ↓
module tree + actual functionality

main.rs
  ↓
library ko use karke executable start karta hai
```

Binary crate library crate ko ek **external user** ki tarah treat karta hai.

> Binary crate sirf library ke **public API** ko use kar sakta hai.

Module tree generally `src/lib.rs` mein define karna better practice hai.

---

## ⬆️ `super` — Parent Module Par Jana

`super` ka matlab:

> **Current module ke parent module par jao.**

Filesystem mein `..` parent directory ke equivalent hai.

Rust mein:

```rust
super::
```

parent module ko refer karta hai.

### Example

```rust
fn deliver_order() {}

mod back_of_house {

    fn fix_incorrect_order() {
        cook_order();

        super::deliver_order();
    }

    fn cook_order() {}
}
```

Module tree:

```text
crate
├── deliver_order
└── back_of_house
    └── fix_incorrect_order
```

`fix_incorrect_order()` ke andar:

```rust
super::deliver_order();
```

means:

```text
current module
      ↓
super
      ↓
parent module = crate
      ↓
deliver_order
```

### Why use `super`?

Agar child aur parent closely related hain aur future mein dono ko ek saath move kar sakte ho, toh `super` useful hai.

---

## 🏛️ Public Structs

Struct ko public banane se:

```rust
pub struct Breakfast {
    pub toast: String,
    seasonal_fruit: String,
}
```

**struct public hota hai, lekin fields automatically public nahi hote.**

```text
Breakfast
├── toast          → public
└── seasonal_fruit → private
```

Isliye:

```rust
meal.toast = String::from("Wheat");
```

allowed hai.

Lekin:

```rust
meal.seasonal_fruit = String::from("blueberries");
```

allowed nahi hai.

---

## ⚠️ Public Struct ≠ Public Fields

```rust
pub struct Breakfast {
    pub toast: String,
    seasonal_fruit: String,
}
```

means:

```text
struct      → public
toast       → public
fruit       → private
```

> **Struct aur uske fields ki privacy independently control hoti hai.**

---

## 🏗️ Private Field Wale Struct ko Construct Karna

Agar struct ka koi field private hai:

```rust
pub struct Breakfast {
    pub toast: String,
    seasonal_fruit: String,
}
```

toh outside code directly struct literal se object nahi bana sakta, because private field ki value set nahi kar sakta.

Isliye public constructor/associated function provide karte hain:

```rust
impl Breakfast {
    pub fn summer(toast: &str) -> Breakfast {
        Breakfast {
            toast: String::from(toast),
            seasonal_fruit: String::from("peaches"),
        }
    }
}
```

Ab outside code:

```rust
let meal = Breakfast::summer("Rye");
```

kar sakta hai.

> **Private fields ko control karne ke liye public associated function constructor ki tarah kaam kar sakta hai.**

---

## 🔢 Public Enums

Agar enum public hai:

```rust
pub enum Appetizer {
    Soup,
    Salad,
}
```

toh **uske saare variants automatically public hote hain.**

```rust
let order1 = Appetizer::Soup;
let order2 = Appetizer::Salad;
```

Alag se variants ke saamne `pub` lagane ki zarurat nahi.

### Remember

```text
pub struct
    ↓
fields private by default

pub enum
    ↓
variants public automatically
```

---

## 🔄 Absolute vs Relative — Which One?

Dono valid hain, but project organization ke according choose karte hain.

Agar definition aur function ko independently move karna likely hai, absolute path useful ho sakta hai:

```rust
crate::front_of_house::hosting::add_to_waitlist();
```

Agar dono closely related hain aur saath move hone ke chances hain, relative path useful ho sakta hai:

```rust
front_of_house::hosting::add_to_waitlist();
```

Rust Book ki general preference **absolute paths** ki hai because definitions aur calls ko independently move karna zyada common ho sakta hai.

---

## 🧠 Complete Mental Model

```text
                    CRATE
                      │
                 Module Tree
                      │
          ┌───────────┴───────────┐
          │                       │
     Absolute                  Relative
          │                       │
     crate::...             current module
                                  │
                         ┌────────┴────────┐
                       self              super
                        │                   │
                   current             parent
```

### Final Cheat Sheet

| Concept | Meaning |
|---|---|
| `crate::` | Crate root se start |
| `self::` | Current module se start |
| `super::` | Parent module se start |
| `::` | Path ke levels separate karta hai |
| `pub mod` | Module public |
| `pub fn` | Function public |
| `pub struct` | Struct public, fields private by default |
| `pub field` | Specific struct field public |
| `pub enum` | Enum ke all variants public |
| `use` | Path ka shortcut |
| Private | Parent se hidden by default |
| Public API | External users ke liye exposed interface |

> **Most important distinction:**
>
> `mod` → module declare karta hai  
> `pub` → accessibility control karta hai  
> `path` → item locate karta hai  
> `use` → path ka shortcut banata hai  
> `super` → parent module par le jaata hai
