# 🦀 GENERIC DATA TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 1. GENERICS — BASIC IDEA

Generics ka purpose:

> **Same logic ko different types ke saath reuse karna,
> bina same code ko baar-baar duplicate kiye.**

Generic type ek **placeholder** hota hai.

Example:

    T

`T` baad mein kisi concrete type ko represent kar sakta hai:

    T = i32
    T = char
    T = f64
    ...


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 2. GENERIC FUNCTION

Suppose largest number find karna hai:

    fn largest(list: &[i32]) -> &i32 {
        let mut largest = &list[0];

        for item in list {
            if item > largest {
                largest = item;
            }
        }

        largest
    }

Yahan:

    list: &[i32]
         ↓
    i32 values ke slice ka reference

    -> &i32
       ↓
    largest i32 value ka reference

### `&i32` vs `&[i32]`

    &i32
      ↓
    ek single i32 ka reference

    &[i32]
      ↓
    i32 values ke slice ka reference

Isliye `largest()` ka input `&[i32]` hai,
kyunki function ko **poori list** chahiye.

Output `&i32` hai, kyunki list mein se
**ek largest element** return hota hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 3. DUPLICATE FUNCTIONS KI PROBLEM

Agar `i32` aur `char` dono ke liye largest find karna ho:

    largest_i32()
        ↓
    same logic

    largest_char()
        ↓
    same logic

Sirf type different hai:

    i32
    char

Logic duplicate ho raha hai.

Generics is duplication ko remove karte hain.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 4. GENERIC `largest()` FUNCTION

Conceptually:

    fn largest<T>(list: &[T]) -> &T

Isko parts mein dekho:

    fn largest<T>
              ↑
          generic type

    list: &[T]
           ↑
    T values ke slice ka reference

    -> &T
       ↑
    T value ka reference

Meaning:

    "Mujhe T type ki values ki list do,
     aur main T type ki largest value ka reference return karunga."

Example:

    T = i32
        ↓
    largest(&[1, 5, 3])

    T = char
        ↓
    largest(&['a', 'z', 'b'])


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 5. `T` KA MATLAB "KOI BHI TYPE" HAI?

Not exactly.

`T` ka matlab:

> **T ek placeholder hai jo kisi type ko represent karta hai.**

Lekin generic function mein jo operations hum `T` par
karna chahte hain, woh type support karta hona chahiye.

Example:

    if item > largest

Yahan `>` comparison required hai.

Problem:

    T = any possible type

Har possible type ko `>` se compare nahi kar sakte.

Isliye compiler error dega.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 6. TRAIT BOUND — `T: PartialOrd`

Compiler suggest karta hai:

    T: PartialOrd

So function:

    fn largest<T: PartialOrd>(list: &[T]) -> &T

Meaning:

> `T` koi bhi type ho sakta hai,
> **lekin us type ko `PartialOrd` behavior provide karna hoga.**

`PartialOrd` yahan comparison capability provide karta hai.

Flow:

    T
    ↓
    must implement PartialOrd
    ↓
    comparison allowed
    ↓
    `item > largest` works

`i32` aur `char` dono comparison support karte hain,
isliye dono ke saath generic function kaam kar sakti hai.

### Core idea:

    Generic
       ↓
    many possible types

    Trait bound
       ↓
    only types having required behavior


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 7. GENERICS IN STRUCTS

Generics functions ke alawa structs mein bhi use ho sakte hain.

    struct Point<T> {
        x: T,
        y: T,
    }

Yahan:

    x → T
    y → T

Ek hi `T` dono fields mein use hua hai.

Therefore `x` aur `y` **same type** hone chahiye.

Example:

    let integer = Point {
        x: 5,
        y: 10,
    };

    T = i32

Therefore:

    Point<i32>


Another:

    let float = Point {
        x: 1.0,
        y: 4.0,
    };

    T = f64

Therefore:

    Point<f64>


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 8. `Point<T>` MEIN `x` AUR `y` SAME TYPE

Because:

    struct Point<T> {
        x: T,
        y: T,
    }

same `T` dono jagah use hua hai.

So:

    Point {
        x: 5,
        y: 10,
    }

valid.

    Point {
        x: 1.0,
        y: 4.0,
    }

valid.

But:

    Point {
        x: 5,
        y: 4.0,
    }

invalid.

Kyun?

    x → i32
    y → f64

But struct says:

    x → T
    y → T

So dono same type hone chahiye.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 9. DIFFERENT TYPES CHAHIYE → `T, U`

Agar `x` aur `y` ko different types allow karne hain:

    struct Point<T, U> {
        x: T,
        y: U,
    }

Ab:

    x → T
    y → U

`T` aur `U` independent type placeholders hain.

Therefore:

    Point {
        x: 5,
        y: 4.0,
    }

can be:

    T = i32
    U = f64

So type:

    Point<i32, f64>

### Difference:

    Point<T>

    x → T
    y → T

    ↓

    x and y MUST be same type


    Point<T, U>

    x → T
    y → U

    ↓

    x and y CAN be different types


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 10. GENERICS IN ENUMS

Rust ke common enums already generics use karte hain.

Example:

    enum Option<T> {
        Some(T),
        None,
    }

`T` = optional value ka type.

Example:

    Some(5)

means:

    Option<i32>


    Some("hello")

means:

    Option<&str>


Same enum definition different types ke saath reuse ho gayi.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 11. `Result<T, E>` BHI GENERIC HAI

Chapter 9 mein use kiya:

    Result<T, E>

Definition conceptually:

    enum Result<T, E> {
        Ok(T),
        Err(E),
    }

Yahan:

    T → success value ka type
    E → error ka type

Example:

    File::open("hello.txt")

returns roughly:

    Result<File, io::Error>

Therefore:

    Ok(file)
       ↓
    T = File

    Err(error)
       ↓
    E = io::Error

### Important:

`Result<File, io::Error>` ka matlab:

> **Either `File` milegi OR `io::Error` milega.**

Dono ek saath nahi.

    Result
      ↓
    ┌───────┐
    ↓       ↓
   Ok      Err
    ↓       ↓
  File    Error


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 12. GENERIC METHODS

Generics methods mein bhi use ho sakte hain.

    struct Point<T> {
        x: T,
        y: T,
    }

Method:

    impl<T> Point<T> {
        fn x(&self) -> &T {
            &self.x
        }
    }

### `impl<T>`

`T` ko implementation ke andar introduce karta hai.

    impl<T>
        ↑
    generic T available

    Point<T>
        ↑
    generic Point

### `fn x`

`x` method ka naam hai.

Call:

    let p = Point { x: 5, y: 10 };

    p.x();


### `&self`

Current `Point` object ka immutable reference.

    p.x()
      ↓
    self = reference to p


### `&self.x`

Current object ke `x` field ka reference.

    self
      ↓
    x field
      ↓
    &self.x

If:

    x = 5

then:

    &self.x
        ↓
       &5

Return type:

    -> &T

isliye method value ki copy nahi,
**field ka reference** return karta hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 13. GENERIC METHOD HAR `T` KE LIYE

    impl<T> Point<T> {
        fn x(&self) -> &T {
            &self.x
        }
    }

Ye implementation generic hai.

So:

    Point<i32>
        ↓
      x()

    Point<f32>
        ↓
      x()

    Point<char>
        ↓
      x()

etc.

Jahan `Point<T>` valid hai,
wahan ye method available ho sakta hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 14. SIRF SPECIFIC TYPE KE LIYE METHOD

Kabhi method sirf ek particular concrete type ke liye chahiye.

Example:

    impl Point<f32> {
        fn distance_from_origin(&self) -> f32 {
            (self.x.powi(2) + self.y.powi(2)).sqrt()
        }
    }

Yahan:

    Point<f32>

**generic declaration nahi hai.**

`f32` ek concrete type hai.

Meaning:

> Ye method sirf `Point<f32>` ke liye available hai.

So:

    Point<f32>
        ↓
    distance_from_origin()
        ↓
       available


    Point<i32>
        ↓
    distance_from_origin()
        ↓
       available nahi


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 15. `powi()` / `sqrt()` KI WAJAH

Distance formula:

    √(x² + y²)

Code:

    (self.x.powi(2) + self.y.powi(2)).sqrt()

Floating-point mathematical operations use kar raha hai.

Isliye example specifically:

    Point<f32>

target karta hai.

### Agar integer-specific method banana hota:

    impl Point<i32> {
        ...
    }

Yahan generic `<T>` declare karne ki zaroorat nahi,
kyunki hum intentionally sirf `i32` ko target kar rahe hain.

### Difference:

    impl<T> Point<T>
         ↑
    generic implementation

    impl Point<f32>
         ↑
    specific implementation


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 16. GENERIC IMPLEMENTATION VS SPECIFIC IMPLEMENTATION

### Generic:

    impl<T> Point<T> {
        fn x(&self) -> &T {
            &self.x
        }
    }

Meaning:

    Point<i32>  → x()
    Point<f32>  → x()
    Point<char> → x()
    ...

### Specific:

    impl Point<f32> {
        fn distance_from_origin(&self) -> f32 {
            ...
        }
    }

Meaning:

    Point<f32> → distance_from_origin()
    Point<i32> → NOT available


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 17. `mixup()` — GENERIC METHOD WITH ITS OWN TYPES

Struct:

    struct Point<X1, Y1> {
        x: X1,
        y: Y1,
    }

Implementation:

    impl<X1, Y1> Point<X1, Y1> {

        fn mixup<X2, Y2>(
            self,
            other: Point<X2, Y2>
        ) -> Point<X1, Y2> {

            Point {
                x: self.x,
                y: other.y,
            }
        }
    }

Ye `Point` ka `mixup()` method ka implementation hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 18. `X1, Y1` VS `X2, Y2`

Yahan 4 generic parameters hain,
but inka role alag hai.

    X1, Y1
       ↓
    current `Point` ke types

    X2, Y2
       ↓
    `other` Point ke types


Struct:

    Point<X1, Y1>

means:

    x → X1
    y → Y1


Method:

    other: Point<X2, Y2>

means:

    other.x → X2
    other.y → Y2


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 19. `mixup()` ACTUALLY KYA KARTA HAI?

Method:

    fn mixup<X2, Y2>(
        self,
        other: Point<X2, Y2>
    ) -> Point<X1, Y2>

Body:

    Point {
        x: self.x,
        y: other.y,
    }

Meaning:

    NEW POINT
       │
       ├── x ← self.x
       │
       └── y ← other.y


So:

    self
      ├── x = 5
      └── y = 10.4

    other
      ├── x = "Hello"
      └── y = 'c'

After:

    self.mixup(other)

new Point:

    x = 5
    y = 'c'


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 20. RETURN TYPE `Point<X1, Y2>` KYUN?

Because:

    x: self.x

`self.x` ka type:

    X1

And:

    y: other.y

`other.y` ka type:

    Y2

Therefore new Point:

    x → X1
    y → Y2

Hence:

    Point<X1, Y2>


### Simple formula:

    self.x
       ↓
      X1

    other.y
       ↓
      Y2

    new Point
       ↓
    Point<X1, Y2>


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 21. `mixup()` EXAMPLE

    let p1 = Point {
        x: 5,
        y: 10.4,
    };

Here:

    p1 = Point<i32, f64>


    let p2 = Point {
        x: "Hello",
        y: 'c',
    };

Here:

    p2 = Point<&str, char>


Now:

    let p3 = p1.mixup(p2);

`mixup()` takes:

    self = p1
    other = p2

It creates:

    x = p1.x
      = 5

    y = p2.y
      = 'c'

Therefore:

    p3 = Point {
        x: 5,
        y: 'c',
    }

Type:

    Point<i32, char>


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 22. STRUCT GENERICS + METHOD GENERICS

Important distinction:

    impl<X1, Y1> Point<X1, Y1>
        ↑
    struct ke generic parameters

And:

    fn mixup<X2, Y2>
             ↑
    method ke additional generic parameters

So:

    X1, Y1
       ↓
    self Point ke types

    X2, Y2
       ↓
    other Point ke types

# 23. GENERICS PERFORMANCE — SLOW HOTE HAIN?

**Normally nahi.**

Rust generics ko compile time par **monomorphization** ke through
concrete types ke specialized code mein convert karta hai.

Example:

    Some(5)

means:

    Option<i32>


    Some(5.0)

means:

    Option<f64>


Compiler conceptually specialized versions generate karta hai:

    Option<i32>

and:

    Option<f64>

So runtime par generic type ko dynamically figure out karne ki
zaroorat nahi hoti.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 24. MONOMORPHIZATION

Simple meaning:

> **Generic code ko compile time par actual concrete types ke
> specialized code mein convert karna.**

Flow:

    Generic source code
          ↓
      compile time
          ↓
    concrete types identify
          ↓
    monomorphization
          ↓
    specialized code
          ↓
       runtime

Example:

    Option<T>

can become conceptually:

    Option<i32>
    Option<f64>
    Option<char>
    ...


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ⭐ COMPLETE MENTAL MODEL

                         GENERICS
                            │
          ┌─────────────────┼─────────────────┐
          ↓                 ↓                 ↓
       Function           Struct             Enum
          ↓                 ↓                 ↓
      largest<T>          Point<T>          Option<T>
          │                 │                 │
          │                 │                 └── Result<T,E>
          │                 │
          │                 └── Methods
          │
          └── Trait bounds
                  ↓
              T: PartialOrd
                  ↓
          required behavior


Then:

    Generic code
         ↓
    compile time
         ↓
    Monomorphization
         ↓
    concrete specialized code
         ↓
    efficient runtime

# ⭐ KEY TAKEAWAYS

🔹 **Generic = type ka placeholder.**

🔹 `T` commonly generic type parameter ke liye use hota hai.

🔹 `&i32` = ek `i32` ka reference.

🔹 `&[i32]` = `i32` values ke slice ka reference.

🔹 `fn largest<T>(list: &[T]) -> &T` same largest-finding
   logic ko different types ke saath reuse karne deta hai.

🔹 Generic `T` automatically har operation support nahi karta.

🔹 `T: PartialOrd` ka matlab `T` ko comparison support karna hoga.

🔹 `struct Point<T>` mein `x` aur `y` same `T` type ke hain.

🔹 `struct Point<T, U>` mein `x` aur `y` different types ke ho sakte hain.

🔹 `Option<T>` aur `Result<T, E>` generics ke real examples hain.

🔹 `Result<T, E>`:
   
       T → success value
       E → error

🔹 `Ok(file)` mein `T = File`.

🔹 `Err(error)` mein `E = io::Error`.

🔹 `Result<File, io::Error>` means **either File or io::Error**,
   dono ek saath nahi.

🔹 `impl<T> Point<T>` generic `Point` ke methods define karta hai.

🔹 `fn x(&self) -> &T` mein:
   
       `x` → method ka naam
       `&self` → current object ka reference
       `&self.x` → x field ka reference
       `&T` → returned reference ka type

🔹 `impl Point<f32>` sirf `Point<f32>` ke liye implementation hai.
   Yahan `f32` generic nahi, concrete type hai.

🔹 `impl Point<i32>` similarly sirf `Point<i32>` ke liye method
   define kar sakta hai.

🔹 `mixup()` ek generic method ka example hai.

🔹 `X1, Y1` → current `Point` ke types.

🔹 `X2, Y2` → `other` Point ke types.

🔹 `mixup()`:
   
       x ← self.x
       y ← other.y

🔹 Isliye return type:

       Point<X1, Y2>

🔹 Example:

       Point<i32, f64>
       +
       Point<&str, char>
       ↓
       Point<i32, char>

🔹 Generics runtime performance ko normally slow nahi karte.

🔹 Rust compile time par **monomorphization** karke generic code ke
   concrete specialized versions generate karta hai.

# 🧠 ONE-LINE SUMMARY

**Generics ek hi code ko different types ke saath reuse karne ka
mechanism hain; traits batate hain ki generic type ko kya behavior
support karna hai, aur Rust compile time par generic code ko concrete
specialized code mein convert karta hai.**
