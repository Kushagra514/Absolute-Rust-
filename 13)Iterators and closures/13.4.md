# PERFORMANCE IN LOOPS VS. ITERATORS

## 1. MAIN QUESTION

`search()` ko do ways mein likh sakte hain:

    for loop
        VS
    iterator


Question:

> Kya iterator version actually slower hai?

Rust Book ne benchmark karke compare kiya.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 2. BENCHMARK

Test mein:

    The Adventures of Sherlock Holmes
        ↓
    poora text ek String mein load
        ↓
    "the" word search


Results:

    for loop:
    19,620,300 ns/iter

    iterator:
    19,234,900 ns/iter


Dono numbers bahut close hain.

Conclusion:

> Dono implementations ki performance almost same hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 3. KYA IS BENCHMARK SE PROVE HUA?

Book ka point ye nahi hai ki:

    "Dono implementations har possible situation
     mein exactly same speed hain."

Benchmark sirf:

    general sense

deta hai ki dono approaches ki performance
roughly comparable hai.


More comprehensive benchmark ke liye different:

    text sizes
    queries
    query lengths
    input variations

test karne padenge.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 4. ITERATORS HIGH-LEVEL HONE KE BAAD BHI FAST KYUN?

Iterator code:

    contents
        .lines()
        .filter(...)
        .collect()


high-level abstraction hai.

Lekin Rust compiler ise optimize karke roughly
usi level ka machine code bana sakta hai jo
manually low-level loop likhne par banta.


Meaning:

    High-level Rust code
          ↓
       compiler
          ↓
    optimized machine code


Isliye abstraction use karne ka matlab
automatically slower code nahi hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 5. ZERO-COST ABSTRACTION

Rust mein iterators ko:

    zero-cost abstraction

kaha jata hai.

Meaning:

> Abstraction use karne se additional runtime
> overhead necessarily add nahi hota.


Simple idea:

    abstraction
        ↓
    cleaner / higher-level code

    BUT

    runtime
        ↓
    unnecessary extra cost nahi


Yaani:

    "What you don't use, you don't pay for."


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 6. ITERATOR VS HAND-WRITTEN CODE

Many cases mein:

    iterator code
        ↓
    compiler optimization
        ↓
    same/similar assembly

as compared to carefully hand-written lower-level code.


Book ka point:

> In many cases, compiler-generated iterator code
> itna efficient hota hai ki manually hand-written
> code se better karna difficult ho sakta hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 7. COMPILER OPTIMIZATIONS

Rust compiler optimizations apply kar sakta hai,
for example:

### Loop unrolling

Normal:

    loop
      ↓
    one iteration at a time


Compiler kabhi operations ko expand/unroll kar sakta hai
taaki loop overhead reduce ho.


### Bounds-check elimination

Array/vector access mein normally compiler/runtime ko
check karna pad sakta hai:

    index valid hai?

Optimization situations mein compiler ye checks
eliminate kar sakta hai jab prove ho ki access safe hai.

Result:

    efficient machine code


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 8. CLOSURES BHI ZERO-COST ABSTRACTIONS KA PART

Closures:

    |x| x + 1

aur iterators:

    .map(...)
    .filter(...)

high-level functional programming style provide karte hain.

Lekin compiler unhe efficiently compile kar sakta hai.

Therefore:

    closures + iterators
          ↓
    expressive code
          +
    low runtime overhead


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 9. PRACTICAL CONCLUSION

Iterator code dekhkar ye assume mat karo:

    iterator
        ↓
    abstraction
        ↓
    slower


Rust mein commonly:

    iterator
        ↓
    high-level readable code
        ↓
    compiler optimization
        ↓
    highly efficient machine code


Therefore readability aur performance
necessarily trade-off nahi hain.

# 🔑 KEY TAKEAWAYS

`for loop` vs `iterator`
    → benchmark mein similar performance.

Benchmark:

    for loop     ≈ 19.62 ms/iteration
    iterator     ≈ 19.23 ms/iteration

Exact numbers universal nahi hain;
different inputs par results change ho sakte hain.

`Iterator`
    → high-level abstraction hai.

`Zero-cost abstraction`
    → abstraction use karne par unnecessary
      runtime overhead nahi hona chahiye.

Rust compiler:
    → iterator/closure code ko optimize kar sakta hai.

Possible optimizations:
    → loop unrolling
    → bounds-check elimination

Important idea:

    High-level code
        ≠
    automatically slow code

# ⭐ CHAPTER 13 FINAL IDEA

    Closures
        +
    Iterators
        ↓
    functional-style,
    expressive Rust code
        ↓
    compiler optimization
        ↓
    low-level efficient machine code


Rust ka goal:

> **High-level expressiveness + low-level performance**

Isi wajah se closures aur iterators ko
**zero-cost abstractions** kaha jata hai.
