# 7.4 — Bringing Paths into Scope with `use`

> **Mental Model**
>
> `use` → long path ka shortcut
>
> `as` → shortcut ko new name do
>
> `pub use` → shortcut ko public/re-export karo
>
> `{}` → multiple imports ko combine karo
>
> `*` → saare public items import karo

---

## 🔗 `use` — Path ka Shortcut

Agar baar-baar long path likhna pade:

```rust
crate::front_of_house::hosting::add_to_waitlist();
```

toh `use` se shortcut bana sakte hain:

```rust
use crate::front_of_house::hosting;

pub fn eat_at_restaurant() {
    hosting::add_to_waitlist();
}
```

`use` ke baad:

```text
crate::front_of_house::hosting
            ↓
          hosting
```

> **`use` item ko move nahi karta. Sirf current scope mein us path ka shortcut banata hai.**

---

## 📍 `use` Sirf Us Scope Mein Apply Hota Hai

```rust
use crate::front_of_house::hosting;

mod customer {
    pub fn eat_at_restaurant() {
        hosting::add_to_waitlist();
    }
}
```

Ye compile nahi karega.

Why?

```text
use
 ↓
root scope mein available

customer
 ↓
alag scope
 ↓
hosting shortcut available nahi ❌
```

Shortcut ko child scope mein bhi chahiye toh wahan `use` karo:

```rust
mod customer {
    use crate::front_of_house::hosting;

    pub fn eat_at_restaurant() {
        hosting::add_to_waitlist();
    }
}
```

Ya parent ke shortcut ko `super` se access kar sakte ho:

```rust
mod customer {
    pub fn eat_at_restaurant() {
        super::hosting::add_to_waitlist();
    }
}
```

> **`use` ka shortcut automatically child scopes mein nahi milta.**

---

## ✅ Idiomatic `use` for Functions

Function ko directly import karne ke bajay uske **parent module** ko import karna idiomatic hai.

### Preferred

```rust
use crate::front_of_house::hosting;

fn eat_at_restaurant() {
    hosting::add_to_waitlist();
}
```

### Usually Avoid

```rust
use crate::front_of_house::hosting::add_to_waitlist;

fn eat_at_restaurant() {
    add_to_waitlist();
}
```

Why?

```text
hosting::add_to_waitlist()
```

dekhte hi clear hai ki function `hosting` module se aa raha hai.

But:

```text
add_to_waitlist()
```

dekhkar pata nahi chalta ki function locally defined hai ya kisi module se.

> **Function ke liye generally parent module import karo.**

---

## 🏛️ Structs, Enums aur Other Items

Structs, enums aur other items ke liye **full path import karna idiomatic hai**:

```rust
use std::collections::HashMap;

fn main() {
    let mut map = HashMap::new();
}
```

Instead of:

```rust
use std::collections;

let map = collections::HashMap::new();
```

### Why?

Convention hai:

```text
Function
→ parent module import

Struct / Enum / Other item
→ item itself import
```

Ye mainly readability/style convention hai, strict language rule nahi.

---

## ⚠️ Same Name Conflict

Suppose do jagah se same naam aa raha hai:

```text
std::fmt::Result
std::io::Result
```

Agar dono directly import karoge:

```rust
use std::fmt::Result;
use std::io::Result;
```

toh scope mein do `Result` names aa jayenge.

Rust nahi jaanta:

```text
Result
  ↓
fmt wala?
ya
io wala?
```

Isliye parent modules import kar sakte hain:

```rust
use std::fmt;
use std::io;

fn function1() -> fmt::Result {
    // ...
}

fn function2() -> io::Result<()> {
    // ...
}
```

Ab names clearly distinguish ho rahe hain:

```text
fmt::Result
io::Result
```

---

## 🏷️ `as` — Import ka Alias

Same-name conflict ka doosra solution `as` hai.

```rust
use std::fmt::Result;
use std::io::Result as IoResult;
```

Ab:

```rust
fn function1() -> Result {
    // ...
}

fn function2() -> IoResult<()> {
    // ...
}
```

### Mental Model

```text
std::io::Result
       ↓ as
    IoResult
```

> **`as` imported item ko current scope mein ek naya local name deta hai.**

---

## 🔄 `pub use` — Re-export

Normal:

```rust
use crate::front_of_house::hosting;
```

shortcut ko **sirf current scope** mein available karta hai.

`pub use`:

```rust
pub use crate::front_of_house::hosting;
```

shortcut ko **public interface ka part** bana deta hai.

Isse external code shorter path use kar sakta hai.

### Pehle Original Structure

```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}
```

Notice:

```text
front_of_house → PRIVATE
hosting        → PUBLIC
add_to_waitlist → PUBLIC
```

Module tree:

```text
restaurant
└── front_of_house          ← PRIVATE
    └── hosting             ← PUBLIC
        └── add_to_waitlist ← PUBLIC
```

External code directly:

```rust
restaurant::front_of_house::hosting::add_to_waitlist();
```

use nahi kar sakta, because `front_of_house` private hai.

### Ab `pub use`

Crate root mein:

```rust
pub use crate::front_of_house::hosting;
```

Ab:

```text
restaurant
│
├── front_of_house          ← PRIVATE
│   └── hosting
│       └── add_to_waitlist
│
└── hosting                 ← PUBLIC RE-EXPORT
    └── add_to_waitlist
```

Important:

> **`hosting` move nahi hua.**
>
> Same `hosting` module ko ab do paths se access kiya ja sakta hai:

```text
Internal path:
crate::front_of_house::hosting

Public re-exported path:
crate::hosting
```

External code ab:

```rust
restaurant::hosting::add_to_waitlist();
```

use kar sakta hai.

But:

```rust
restaurant::front_of_house::hosting::add_to_waitlist();
```

abhi bhi allowed nahi hai because:

```text
front_of_house → PRIVATE
```

> **`pub use` private module ko public nahi banata. Ye uske andar ke selected item ke liye ek naya public path/doorway provide karta hai.**

### Why Re-export?

Internal structure aur public API ko alag rakhne ke liye.

```text
Internal structure
      ↓
developer-friendly

Public API
      ↓
user-friendly
```

## 📦 External Packages

External crate use karne ke basic steps:

### 1. `Cargo.toml` mein dependency

```toml
[dependencies]
rand = "0.8.5"
```

Cargo:

```text
Cargo.toml
   ↓
dependency download
   ↓
rand crate available
```

### 2. Code mein `use`

```rust
use rand::Rng;
```

External crate ka naam absolute path ka starting point hota hai:

```rust
rand::thread_rng()
```

---

## 🎲 `rand` Example

```rust
use rand::Rng;

fn main() {
    let secret_number = rand::thread_rng().gen_range(1..=100);
}
```

Yahan:

```text
rand::thread_rng()
        ↓
ThreadRng object

gen_range()
        ↓
Rng trait ka method
```

`use rand::Rng;` trait ko scope mein laata hai so `gen_range()` method lookup mein available ho.

---

## 📚 `std` bhi Ek Crate Hai

`std` bhi technically ek external crate hai:

```rust
use std::collections::HashMap;
```

Difference:

> Standard library Rust ke saath ship hoti hai, isliye `Cargo.toml` mein dependency add nahi karni padti.

`std` se path:

```text
std::collections::HashMap
```

ek absolute path hai jo `std` crate se start hota hai.

---

## 🧹 Nested `use` Paths

Agar multiple imports ka common path same hai:

```rust
use std::cmp::Ordering;
use std::io;
```

toh combine kar sakte hain:

```rust
use std::{cmp::Ordering, io};
```

### Mental Model

Common part:

```text
std::
```

Different parts:

```text
cmp::Ordering
io
```

So:

```rust
use std::{cmp::Ordering, io};
```

---

## 🪆 Nested Paths at Any Level

Nested paths kisi bhi common subpath par use ho sakte hain.

Example:

```rust
use std::io;
use std::io::Write;
```

Common path:

```text
std::io
```

Combine:

```rust
use std::io::{self, Write};
```

Ye dono ko scope mein laata hai:

```text
std::io
std::io::Write
```

### `self` Yahan Kya Hai?

```rust
use std::io::{self, Write};
```

`self` means:

> **Current path/module khud.**

So:

```text
self  → std::io
Write → std::io::Write
```

Equivalent to:

```rust
use std::io;
use std::io::Write;
```

---

## 🌐 Glob Operator `*`

Agar kisi path ke **saare public items** current scope mein laane hain:

```rust
use std::collections::*;
```

`*` = glob operator.

Conceptually:

```text
std::collections
├── HashMap
├── HashSet
├── VecDeque
└── ...
       ↓
current scope
```

---

## ⚠️ Glob Se Caution

Glob convenient hai, but problems create kar sakta hai.

### 1. Source unclear ho jata hai

```rust
use some_crate::*;
```

Phir:

```rust
HashMap::new();
```

dekhkar immediately pata nahi chalega ki `HashMap` kahaan se aaya.

### 2. Dependency update problem

Aaj:

```text
some_crate
├── Foo
└── Bar
```

Aur tum:

```rust
use some_crate::*;
```

karte ho.

Kal dependency update mein:

```text
some_crate
├── Foo
├── Bar
└── Data   ← new item
```

add ho gaya.

Ab `Data` bhi automatically current scope mein aa jayega.

Agar tumhara khud ka bhi:

```rust
struct Data;
```

hai, toh name conflict ho sakta hai.

> **Glob ka matlab: aaj ke saare public names + future mein add hone wale public names bhi scope mein aa sakte hain.**

---

## ✅ Glob Kab Useful Hai?

Glob commonly useful hota hai:

- Tests mein saare tested items ko `tests` module mein laane ke liye
- Prelude-style patterns mein

Normal application code mein specific imports generally zyada clear hote hain.

---

# 🧠 Complete `use` Cheat Sheet

| Syntax | Meaning |
|---|---|
| `use crate::x::y;` | `y`/path ka shortcut banao |
| `use crate::x::module;` | Module ko scope mein lao |
| `use crate::x::func;` | Function ko directly lao |
| `use crate::x::Type;` | Type ko scope mein lao |
| `use ... as Name;` | Imported name ka alias |
| `pub use ...;` | Import + re-export |
| `use std::{A, B};` | Multiple imports combine karo |
| `use std::io::{self, Write};` | `std::io` + `std::io::Write` |
| `use std::*;` | Saare public items import |
| `use rand::Rng;` | External crate se item/trait import |

---

## 🔥 Most Important Rules

```text
1. use = shortcut, creation nahi

2. use sirf us scope mein apply hota hai
   jahan likha gaya hai

3. Functions ke liye:
   parent module import karna idiomatic hai

   use crate::hosting;
   hosting::add_to_waitlist();

4. Struct / Enum / other items ke liye:
   full path import karna idiomatic hai

   use std::collections::HashMap;

5. Same-name conflict:
   parent modules use karo
   OR
   `as` se alias do

6. pub use:
   shortcut ko public API mein re-export karo

7. External crate:
   Cargo.toml dependency
   +
   use/path

8. std external crate hai,
   but Cargo.toml mein dependency add nahi karni

9. `{}` nested paths:
   common path ko combine karne ke liye

10. self:
    current path/module khud

11. *:
    saare public items import

12. Glob convenient hai but
    names unclear + dependency updates se conflicts possible

13. pub use:
    private internal structure ko hide rakh kar
    selected item ke liye ek simple public path provide
    kar sakta hai
```

> **Final Mental Model**
>
> `mod` → module declare karta hai  
> `path` → item locate karta hai  
> `use` → path ka shortcut banata hai  
> `as` → shortcut ko alias deta hai  
> `pub use` → shortcut ko publicly re-export karta hai  
> `{}` → multiple related imports combine karta hai  
> `self` → current item/module  
> `*` → all public items
