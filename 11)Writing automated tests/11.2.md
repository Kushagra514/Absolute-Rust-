# 🦀 RUST BOOK — CHAPTER 11.2
# CONTROLLING HOW TESTS ARE RUN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


# 🧪 1. `cargo test` ACTUALLY KYA KARTA HAI?

Jaise:

    cargo run

code compile karke binary run karta hai,

waise:

    cargo test

code ko test mode mein compile karta hai
aur test binary run karta hai.

Flow:

    cargo test
        ↓
    code compile
        ↓
    test binary build
        ↓
    tests run
        ↓
    PASS / FAIL report


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ⚡ 2. DEFAULT MEIN TESTS PARALLEL RUN HOTE HAIN

Agar multiple tests hain:

    test A
    test B
    test C

toh default:

    A ──────────┐
    B ──────────┼──→ simultaneously
    C ──────────┘

Rust multiple threads use karta hai.

### Fayda:

    parallel
       ↓
    faster execution
       ↓
    faster feedback


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ⚠️ 3. PARALLEL TESTS KI PROBLEM

Tests ko:

    ❌ ek dusre par depend nahi karna chahiye

Aur:

    ❌ shared state use karke ek dusre ko affect nahi karna chahiye.


Example:

    Test A
       ↓
    test-output.txt mein "A" write

    Test B
       ↓
    same file mein "B" write

Parallel execution:

    A ──→ file
          ↓
    B ──→ same file
          ↓
    A ka data overwrite ho sakta hai

Result:

    Test A / B
        ↓
    unexpected result
        ↓
    test FAIL


Important:

Code necessarily wrong nahi hai.

Problem ho sakti hai:

    tests interfering with each other


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 📂 4. SHARED STATE KE EXAMPLES

Shared state sirf files nahi hoti.

Tests ko carefully handle karna chahiye agar woh
same:

    file
    current working directory
    environment variables
    other shared resources

use kar rahe hain.

Example:

    Test A → environment variable change
    Test B → same variable read

Parallel run hone par Test B ko unexpected value mil sakti hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🔒 5. TESTS KO ONE-BY-ONE KAISE RUN KARE?

Command:

    cargo test -- --test-threads=1

Yahan:

    --test-threads=1

test binary ko bolta hai:

> **Sirf 1 thread use karo.**

So:

    Test A
       ↓
    finish

    Test B
       ↓
    finish

    Test C
       ↓
    finish


No parallelism.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🧠 6. `--test-threads=1` KA TRADE-OFF

Parallel:

    multiple threads
        ↓
      faster

Single thread:

    one test at a time
        ↓
      slower

Lekin:

    shared state interference
        ↓
      avoid ho sakta hai


Use when:

> Tests ko shared state ki wajah se ek dusre se
> interfere karne ka risk ho.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🔀 7. `cargo test` AUR TEST BINARY KE OPTIONS

Important concept:

Kuch options:

    cargo test

ko jaate hain.

Kuch options:

    test binary

ko jaate hain.

Dono ko separate karne ke liye:

    --

separator use hota hai.

General structure:

    cargo test [cargo options] -- [test binary options]


Example:

    cargo test -- --test-threads=1

Yahan:

    cargo test
         ↓
    Cargo command

    --
         ↓
    separator

    --test-threads=1
         ↓
    test binary ka option


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ❓ 8. HELP OPTIONS

Cargo test ke available options dekhne ke liye:

    cargo test --help

Test binary ke options dekhne ke liye:

    cargo test -- --help


Difference:

    cargo test --help
          ↓
    cargo ke options


    cargo test -- --help
          ↓
    test binary ke options

# 🖨️ 9. TEST OUTPUT DEFAULT MEIN HIDE KYUN HOTA HAI?

Suppose test ke andar:

    println!("Hello");

Agar test PASS ho:

    cargo test

default mein:

    "Hello"

terminal par nahi dikhega.

Rust test output ko:

    capture

kar leta hai.

Meaning:

    test ke stdout
         ↓
      capture
         ↓
    normally hide


Purpose:

> Terminal ko unnecessary `println!` output se
> clutter hone se bachana aur test results ko readable rakhna.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ❌ 10. FAILING TEST KA OUTPUT DIKHTA HAI

Agar test fail ho:

    println!("Hello");

toh captured output failure report ke saath show hota hai.

Example:

    ---- tests::this_test_will_fail stdout ----

    I got the value 8

    assertion `left == right` failed
    left: 10
    right: 5


So default behavior:

    PASS test
       ↓
    println output hidden


    FAIL test
       ↓
    println output shown


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 👀 11. PASSING TESTS KA OUTPUT BHI KAISE DIKHAYE?

Use:

    cargo test -- --show-output

Meaning:

> **Successful tests ka captured stdout bhi show karo.**

Now:

    PASS test
       ↓
    println output visible

    FAIL test
       ↓
    println output visible


Example:

    successes:

    ---- tests::this_test_will_pass stdout ----

    I got the value 4


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🔄 12. DEFAULT VS `--show-output`

### Default:

    cargo test

    PASS
      ↓
    output captured/hidden

    FAIL
      ↓
    output shown


### With:

    cargo test -- --show-output

    PASS
      ↓
    output shown

    FAIL
      ↓
    output shown

# 🎯 13. SAARE TESTS RUN KARNA HAMESHA NECESSARY NAHI

Suppose project mein:

    100 tests

hain.

Tum sirf ek specific function par kaam kar rahe ho.

Har baar:

    cargo test

run karne se:

    100 tests
        ↓
    all execute


Ye unnecessarily slow ho sakta hai.

Rust tumhe specific tests run karne deta hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🔎 14. SINGLE TEST RUN KARNA

Suppose tests:

    add_two_and_two
    add_three_and_two
    one_hundred

Agar sirf:

    one_hundred

run karna hai:

    cargo test one_hundred


Flow:

    cargo test one_hundred
           ↓
    matching test
           ↓
    one_hundred
           ↓
          run


Output:

    running 1 test

    test tests::one_hundred ... ok

    2 filtered out


Meaning:

    1 test run hua
    2 tests filter out ho gaye


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🧠 15. TEST NAME FILTERING

Command:

    cargo test one_hundred

Rust test names mein match karta hai.

Sirf matching test run hota hai.

Non-matching tests:

    filtered out


So:

    3 total tests

    one_hundred → match
    add_two_and_two → no
    add_three_and_two → no

Result:

    1 run
    2 filtered out


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ⚠️ 16. MULTIPLE TEST NAMES DIRECTLY NAHI DE SAKTE

Ye:

    cargo test test1 test2

is tarah multiple test names specify karne ka
supported method nahi hai.

`cargo test` is context mein sirf first value ko use karega.

Lekin multiple tests run karne ka doosra method hai:

    partial-name filtering


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🔍 17. PARTIAL NAME SE MULTIPLE TESTS RUN KARNA

Suppose:

    add_two_and_two
    add_three_and_two
    one_hundred

Do tests ke naam mein:

    add

hai.

Command:

    cargo test add


Rust:

    test name contains "add"?
         ↓
      YES → run
      NO  → filter out


Result:

    add_two_and_two   → run
    add_three_and_two → run
    one_hundred       → filtered out


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 📊 18. FILTERING OUTPUT

Command:

    cargo test add

Output roughly:

    running 2 tests

    test tests::add_three_and_two ... ok
    test tests::add_two_and_two ... ok

    test result: ok.
    2 passed;
    0 failed;
    0 ignored;
    0 measured;
    1 filtered out


Meaning:

    total tests = 3

    matched = 2
    filtered out = 1

# 🧩 19. MODULE NAME BHI TEST NAME KA PART HAI

Suppose:

    mod tests {
        #[test]
        fn add_two() {
            ...
        }
    }

Test ka name internally:

    tests::add_two

hai.

Module ka naam:

    tests

test name ka part hai.

Therefore module name se bhi filtering kar sakte ho.

Example:

    cargo test tests


Meaning:

> `tests` naam wale module ke tests ko match karo.

# ⏳ 20. KUCH TESTS BAHUT SLOW HO SAKTE HAIN

Suppose:

    normal tests
        ↓
    few milliseconds

But:

    expensive_test
        ↓
    1 hour

Aise tests ko har:

    cargo test

run ke saath run karna inefficient ho sakta hai.

Rust iske liye:

    #[ignore]

attribute provide karta hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🚫 21. `#[ignore]`

Example:

    #[test]
    #[ignore]
    fn expensive_test() {
        // expensive code
    }

Meaning:

> **Ye test normal `cargo test` run mein skip karo.**

So:

    cargo test

    normal test
        ↓
      RUN

    expensive_test
        ↓
      IGNORED


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 📊 22. `#[ignore]` KA OUTPUT

Example:

    running 2 tests

    test tests::expensive_test ... ignored
    test tests::it_works ... ok

Summary:

    test result: ok.
    1 passed;
    0 failed;
    1 ignored;


Important:

`ignored` ka matlab:

    test fail nahi hua.

It means:

> **Test run hi nahi kiya gaya because it was marked ignored.**

# ▶️ 23. SIRF IGNORED TESTS KAISE RUN KARE?

Command:

    cargo test -- --ignored

Meaning:

> **Sirf `#[ignore]` marked tests run karo.**

Example:

    #[ignore]
    fn expensive_test() {
        ...
    }

Command:

    cargo test -- --ignored

Result:

    expensive_test
         ↓
        RUN

# 🔥 24. ALL TESTS RUN KARNA — INCLUDING IGNORED

Agar:

    normal tests
    +
    ignored tests

sab run karne hain:

    cargo test -- --include-ignored


Meaning:

> **Ignored tests ko bhi include karke all tests run karo.**


Flow:

    cargo test -- --include-ignored

        ↓

    normal tests
        +
    #[ignore] tests
        ↓
      RUN ALL

    cargo test

# 🔑 29. KEY TAKEAWAYS

🔹 `cargo test` code ko test mode mein compile karke
   test binary run karta hai.

🔹 Default mein tests parallel threads par run hote hain.

🔹 Parallel tests ko ek dusre ke shared state ko modify karke
   interfere nahi karna chahiye.

🔹 Shared state mein files, current working directory,
   environment variables, etc. aa sakte hain.

🔹 Tests ko sequentially run karne ke liye:

       cargo test -- --test-threads=1

🔹 `--` Cargo ke arguments aur test binary ke arguments
   ko separate karta hai.

🔹 `cargo test --help` Cargo ke options dikhata hai.

🔹 `cargo test -- --help` test binary ke options dikhata hai.

🔹 Passing tests ka `println!` output default mein captured
   hota hai aur normally terminal par nahi dikhta.

🔹 Failing tests ka captured output failure report mein
   dikhta hai.

🔹 Passing tests ka output bhi dekhna ho:

       cargo test -- --show-output

🔹 Specific test run karne ke liye:

       cargo test test_name

🔹 `filtered out` ka matlab test match nahi hua aur run nahi hua.

🔹 Partial name se multiple tests run kiye ja sakte hain:

       cargo test add

🔹 Test ke module ka naam bhi test name ka part hota hai,
   isliye module name se bhi filtering possible hai.

🔹 Expensive/slow tests ko:

       #[ignore]

   se normal test runs se exclude kar sakte ho.

🔹 Sirf ignored tests:

       cargo test -- --ignored

🔹 Normal + ignored tests:

       cargo test -- --include-ignored

🔹 `ignored` ka matlab FAILED nahi hota.
   Iska matlab test intentionally current run mein execute nahi hua.
