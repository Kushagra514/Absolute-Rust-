# 🦀 RUST ERROR HANDLING — `panic!`
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 💥 1. `panic!` KYA HOTA HAI?

Kabhi program aisi situation mein pahunch jaata hai jahan safely continue karna possible nahi hota.

Aise case mein Rust ka:

    panic!

macro program ko stop kar deta hai.

### `panic!` do tarah se ho sakta hai:

    1. Hum khud `panic!` call karein

        panic!("crash and burn");


    2. Koi operation automatically panic cause kare

        let v = vec![1, 2, 3];

        v[99];

        ↑
        Invalid index → panic!


### 🧠 Mental Model

    Something seriously wrong
              ↓
           panic!
              ↓
       Error message
              ↓
       Stack cleanup
              ↓
       Program terminates

# 🧹 2. PANIC HONE PAR RUST KYA KARTA HAI?

By default Rust:

    panic
      ↓
    failure message print
      ↓
    stack unwind
      ↓
    data/resources cleanup
      ↓
    program quit

Default behavior ko **unwinding** kehte hain.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🔄 3. STACK UNWINDING KYA HAI?

Suppose functions aise call hui:

    main()
      ↓
    function_a()
      ↓
    function_b()
      ↓
    function_c()
      ↓
    PANIC!

Panic hone ke baad Rust stack ko reverse direction mein walk karta hai:

    function_c()
         ↓
    function_b()
         ↓
    function_a()
         ↓
    main()

Har function se related data/resources ko clean up karta hai.

### 🧠 Simple Meaning

**Unwinding = panic ke baad Rust stack ko reverse direction mein walk karke cleanup karta hai.**

⚠️ Unwinding computationally expensive ho sakta hai kyunki Rust ko
stack walk aur cleanup karna padta hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🛑 4. UNWINDING vs ABORTING

Rust panic ke response mein do approaches use kar sakta hai:

    1. Unwind
    2. Abort


### 🟢 UNWIND — Default

    panic
      ↓
    stack unwind
      ↓
    cleanup
      ↓
    program ends


### 🔴 ABORT

    panic
      ↓
    immediately abort
      ↓
    program ends

Abort mein Rust stack ko unwind karke cleanup nahi karta.

Program ki memory ko baad mein operating system clean up kar sakta hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 📦 5. "BINARY SMALL" KA KYA MATLAB HAI?

**Binary = compiled executable program.**

Linux mein example:

    my_program

Windows mein:

    my_program.exe

Rust code compile hone ke baad final executable file banti hai.

Normal unwinding support ke liye binary mein unwinding se related
machinery/code bhi include ho sakta hai.

Agar:

    [profile.release]
    panic = 'abort'

use karte ho, to release build mein panic par Rust unwind nahi karega;
directly abort karega.

Isse unwinding machinery ki zaroorat kam ho sakti hai, aur **final
executable/binary potentially smaller ho sakti hai.**

Example concept:

    Normal release binary
        ↓
    panic → unwind support
        ↓
    comparatively more code

    Abort release binary
        ↓
    panic → immediate abort
        ↓
    potentially smaller binary

⚠️ Exact size reduction fixed nahi hoti.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ⚙️ 6. PANIC PAR ABORT ENABLE KARNA

`Cargo.toml` mein:

    [profile.release]
    panic = 'abort'

Ab release build mein:

    panic!
      ↓
    immediate abort

instead of:

    panic!
      ↓
    unwind
      ↓
    cleanup
      ↓
    terminate

### `src/main.rs:2:5` ka meaning:

    src/main.rs
         ↓
       file

    2
    ↓
    line 2

    5
    ↓
    column 5

Yani Rust bata raha hai ki panic source code mein
**exactly kahan trigger hua.**

# 🔎 8. PANIC HAMESHA HAMARE `panic!` SE NAHI AATA

Kabhi hum directly:

    panic!("...");

nahi likhte.

Phir bhi program panic kar sakta hai.

Example:

    let v = vec![1, 2, 3];

    v[99];

Yahan humne `panic!` manually call nahi kiya.

Rust ke vector/indexing implementation ne invalid index detect karke
panic cause kiya.

Isliye panic location kabhi:

    tumhara code

aur kabhi:

    library / standard library ka code

ho sakta hai.

Aise cases mein **backtrace** useful hota hai.

# 🚨 9. INVALID VECTOR INDEX

Example:

    fn main() {
        let v = vec![1, 2, 3];

        v[99];
    }

Vector mein:

    Index     Value

      0         1
      1         2
      2         3

Lekin hum:

    v[99]

access kar rahe hain.

Index `99` exist nahi karta.

Therefore:

    vector length = 3
    requested index = 99

    99 >= 3
       ↓
    OUT OF BOUNDS
       ↓
    panic!


### ⚠️ Important

Indexing zero se start hoti hai.

Isliye:

    1st element → index 0
    2nd element → index 1
    3rd element → index 2

Vector mein 3 elements hone ka matlab valid indexes:

    0, 1, 2

hain.

# 🛡️ 10. RUST INVALID INDEX KO KYUN ROKTA HAI?

C jaise languages mein out-of-bounds memory read dangerous ho sakta hai.

Conceptually:

    Array:
    ┌────┬────┬────┐
    │ 10 │ 20 │ 30 │
    └────┴────┴────┘
      0    1    2

Array ke baad memory mein doosra data ho sakta hai:

    ┌────┬────┬────┬───────────────┐
    │ 10 │ 20 │ 30 │ other memory  │
    └────┴────┴────┴───────────────┘

Agar program array ke boundary ke bahar read kare,
to woh unintended memory se data read kar sakta hai.

Isse **buffer overread** ho sakta hai.

Agar attacker indexing ko manipulate kar sake, to potentially
aisa data read ho sakta hai jo usse nahi milna chahiye.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🔐 11. RUST KYA CHECK KARTA HAI?

Yahan ek important distinction hai.

Rust ye check nahi karta:

    "Kya is memory address par password hai?"
    "Kya yahan sensitive information hai?"
    "Kya ye data private hai?"

Rust ka relevant check hai:

    "Kya requested index is vector ke valid range mein hai?"

Example:

    let v = vec![10, 20, 30];

    v[1];

Rust conceptually check karta hai:

    index < v.len() ?

    1 < 3
      ↓
     YES
      ↓
    access allowed


Lekin:

    v[99];

    99 < 3 ?
       ↓
       NO
       ↓
    panic!


### 🧠 Core Point

**Rust sensitive-data detector nahi hai.**

Rust invalid memory access ko prevent karta hai;
woh memory mein stored information ko classify karke
"sensitive" ya "non-sensitive" decide nahi karta.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# 🎯 12. AGAR SENSITIVE DATA VALID MEMORY ADDRESS PAR HO?

Ye important distinction hai.

Agar sensitive data kisi valid object/location mein hai aur
program legitimately us data ko access karne deta hai:

    Rust us access ko automatically block nahi karega.

Example:

    let password = "secret";

    println!("{password}");

Ye valid access hai.

Rust ye nahi bolega:

    "Ye password hai, isko access mat karo."

### Rust ka goal:

    Legitimate / valid access
          ↓
        ALLOW

    Invalid memory access
          ↓
        PREVENT


So Rust **sensitive data ko detect karke protect nahi karta**.

Rust memory-safety rules enforce karta hai.

# 🧠 13. BUFFER OVERREAD KO SIMPLE WAY MEIN SAMJHO

Suppose:

    vector:
    ┌────┬────┬────┐
    │ 10 │ 20 │ 30 │
    └────┴────┴────┘
      0    1    2

Tum request karte ho:

    v[99]

Problem ye nahi hai ki address `99` necessarily
"invalid computer memory" hai.

Problem ye hai:

    99 is NOT an element of this vector.

Rust safe indexing mein:

    vector boundary
          ↓
    index check
          ↓
    out of bounds
          ↓
        panic!

Isliye vector ke bahar ki adjacent memory ko
safe indexing ke through read nahi kar sakte.

# 🔙 14. BACKTRACE KYA HOTA HAI?

Backtrace = panic tak pahunchne wali
**function-call chain ki list**.

Suppose:

    main()
      ↓
    foo()
      ↓
    bar()
      ↓
    library_function()
      ↓
    panic!

Backtrace roughly ye chain dikhayega.

Isse pata lag sakta hai ki panic tak program
kaise pahucha.

# 🧪 15. `RUST_BACKTRACE=1`

Normal panic message mein Rust bol sakta hai:

    note: run with `RUST_BACKTRACE=1`
    environment variable to display a backtrace

Linux/macOS:

    RUST_BACKTRACE=1 cargo run

Ab Rust panic ke saath function-call stack bhi show karega.

### More detailed version:

    RUST_BACKTRACE=full cargo run

`full` zyada verbose backtrace provide kar sakta hai.

# 🔍 16. BACKTRACE KO KAISE READ KARNA HAI?

Backtrace bahut bada ho sakta hai:

    0: Rust internal code
    1: Rust internal code
    2: Rust internal code
    3: standard library
    4: standard library
    5: library code
    6: src/main.rs:4
    7: Rust internal code

### ⭐ Golden Rule

**Backtrace ko top se read karo aur first line dhundo
jahan tumhari khud ki source file appear ho.**

Example:

    6: panic::main
       at ./src/main.rs:4:6

Ye important line hai.

Matlab problem tumhare:

    src/main.rs
    line 4
    column 6

se related hai.

Us point se investigation start karo.

# 🐛 18. PANIC DEBUG KARNE KA PROCESS

Jab future mein panic aaye:

### STEP 1 — Panic message padho

Example:

    index out of bounds:
    the len is 3 but the index is 99


### STEP 2 — File + line dekho

    src/main.rs:4:6


### STEP 3 — Agar zaroorat ho toh backtrace lo

    RUST_BACKTRACE=1 cargo run


### STEP 4 — Backtrace mein apni first source file dhundo

    ./src/main.rs:4:6


### STEP 5 — Us line par dekho kya galat operation/value hai

Example:

    v[99]

### STEP 6 — Determine karo:

    Code kya kar raha tha?
    Kis value ke saath kar raha tha?
    Woh value invalid situation kaise create kar rahi thi?
    Program ko instead kya karna chahiye?

# 🔥 20. `panic!` KA MAIN PURPOSE

`panic!` ka use tab hota hai jab program
**unrecoverable situation** mein pahunch jaata hai.

Meaning:

    Program safely continue nahi kar sakta
                 ↓
              panic!


Ye har normal error ke liye automatically best solution nahi hai.

Rust next section mein **`Result`** introduce karta hai,
jiska use recoverable errors handle karne ke liye hota hai.

# 🧠 FINAL MENTAL MODEL

                    ERROR
                      │
             ┌────────┴────────┐
             │                 │
       Recoverable       Unrecoverable
             │                 │
          Result            panic!
             │                 │
      handle/recover       program stops


### `panic!`

    panic!
      ↓
    error message
      ↓
    ┌───────────────┐
    │               │
    ↓               ↓
    Unwind         Abort
    ↓               ↓
    cleanup       immediate
    ↓             termination
    terminate


### Invalid indexing

    let v = vec![1, 2, 3];

    v[99];

    length = 3
    valid indexes = 0,1,2
    requested = 99
             ↓
        out of bounds
             ↓
           panic!


### Backtrace

    RUST_BACKTRACE=1 cargo run
                ↓
            backtrace
                ↓
       top se read karo
                ↓
    first file jo tumne khud likhi
                ↓
      investigation start there

# ⭐ KEY TAKEAWAYS

🔹 `panic!` program ko unrecoverable situation mein terminate karta hai.

🔹 Panic manually bhi trigger kar sakte ho aur kuch invalid operations
   automatically panic cause kar sakte hain.

🔹 Default panic behavior **unwinding** hai — Rust stack ko walk karke
   cleanup karta hai.

🔹 `panic = 'abort'` use karne par panic ke time directly abort hota hai,
   aur release binary potentially smaller ho sakti hai.

🔹 Vector mein invalid index use karne par Rust panic karta hai.

🔹 Rust ka bounds check ye decide nahi karta ki memory mein sensitive data hai
   ya nahi; woh check karta hai ki index requested collection ke valid range
   mein hai ya nahi.

🔹 Isliye agar sensitive data kisi valid object mein hai aur program
   legitimately usko expose karta hai, Rust automatically usko block nahi karega.

🔹 Safe Rust ka important guarantee **invalid memory access ko prevent karna**
   hai, sensitive-data detection karna nahi.

🔹 `RUST_BACKTRACE=1 cargo run` panic tak pahunchne wali function-call chain
   dikhata hai.

🔹 Backtrace mein top se read karke **first location jo tumhari own source
   file mein ho** usse investigation start karni chahiye.
