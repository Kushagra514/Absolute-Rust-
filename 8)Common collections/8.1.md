# 8.1 — Storing Lists of Values with Vectors

> **Mental Model**
>
> `Vec<T>` → same type ke multiple values ko ek list mein store karta hai
>
> `Vec<T>` → values memory mein contiguous (saath-saath) store karta hai
>
> `T` → vector mein kis type ke elements hain

---

## 📦 Vector Kya Hai?

`Vec<T>` ko **vector** kehte hain.

Ye ek hi data structure mein multiple values store karta hai.

```text
Vec<T>
├── element
├── element
├── element
└── ...
```

### Important

- Vector mein saare elements **same type** ke hone chahiye.
- Elements memory mein **contiguous** yani paas-paas store hote hain.
- Lists ke liye useful hai, jaise:
  - file ki lines
  - shopping cart ke prices
  - numbers ki list

---

## 🆕 Creating a New Vector

Empty vector banane ke liye:

```rust
let v: Vec<i32> = Vec::new();
```

Yahan:

```text
Vec<i32>
   ↓
vector ke elements i32 honge
```

### Type Annotation Kyun?

Vector empty hai:

```rust
let v = Vec::new();
```

Rust ko abhi pata nahi ki future mein isme kis type ke values aayengi.

Isliye:

```rust
let v: Vec<i32> = Vec::new();
```

mein explicitly batate hain ki:

> `v` sirf `i32` values store karega.

> **Empty `Vec::new()` mein type inference ke liye aksar type annotation ki zarurat hoti hai.**

---

## 🧠 `Vec<T>` aur Generics

`Vec<T>` generic type hai.

```text
Vec<T>
  ↓
T = element ka type
```

Examples:

```rust
Vec<i32>
Vec<String>
Vec<f64>
```

Same `Vec` structure different element types ke liye use ho sakta hai.

---

## ⚡ `vec!` Macro

Aksar vector initial values ke saath banate hain:

```rust
let v = vec![1, 2, 3];
```

Yahan Rust automatically infer karta hai:

```text
v → Vec<i32>
```

because values `1`, `2`, `3` integer hain.

Isliye type annotation ki zarurat nahi:

```rust
let v = vec![1, 2, 3];
```

> **Initial values diye ho toh Rust usually element type infer kar leta hai.**

---

## ✏️ Updating a Vector

Vector mein elements add karne ke liye `push()` use karte hain:

```rust
let mut v = Vec::new();

v.push(5);
v.push(6);
v.push(7);
v.push(8);
```

Result:

```text
v = [5, 6, 7, 8]
```

### `mut` Kyun?

Vector ko modify kar rahe hain, isliye:

```rust
let mut v = Vec::new();
```

hona chahiye.

Without `mut`:

```rust
let v = Vec::new();
v.push(5); // ❌
```

> **Vector ko change karna hai → variable `mut` hona chahiye.**

Yahan Rust `i32` infer kar leta hai because pushed values integers hain.

---

## 📖 Reading Elements

Vector ke element ko access karne ke 2 common ways hain:

1. Indexing: `[]`
2. `get()` method

Example:

```rust
let v = vec![1, 2, 3, 4, 5];
```

### 1. Indexing

```rust
let third: &i32 = &v[2];

println!("The third element is {third}");
```

Indexing **0 se start** hoti hai:

```text
Index:    0   1   2   3   4
Value:    1   2   3   4   5
                 ↑
              third
```

Isliye:

```rust
v[2]
```

third element hai.

---

### 2. `get()`

```rust
let third: Option<&i32> = v.get(2);

match third {
    Some(third) => println!("The third element is {third}"),
    None => println!("There is no third element."),
}
```

`get()`:

```text
valid index
    ↓
Some(&element)

invalid index
    ↓
None
```

> **`get()` `Option<&T>` return karta hai.**

---

## ⚔️ `[]` vs `get()`

Dono same element access kar sakte hain, but invalid index par behavior different hai.

| Method | Invalid index |
|---|---|
| `v[index]` | **panic** |
| `v.get(index)` | **`None`** |

### Example

```rust
let v = vec![1, 2, 3, 4, 5];
```

Invalid access:

```rust
let x = &v[100];
```

→ program **panic** karega.

But:

```rust
let x = v.get(100);
```

→ `None` milega.

---

## 🤔 Kab Kaunsa Use Karein?

### `[]`

Use karo jab:

> Tum sure ho ki index valid hai aur invalid access par program ko panic karna acceptable hai.

```rust
let value = &v[2];
```

### `get()`

Use karo jab:

> Invalid index normal possibility ho sakta hai.

Example:

```text
User ne index enter kiya
        ↓
index galat ho sakta hai
        ↓
get()
        ↓
Some / None handle karo
```

Ye crash ke bajay controlled behavior deta hai.

---

## 🔐 Vector + Borrow Checker

Vector se reference lene par normal ownership/borrowing rules apply hote hain.

Example:

```rust
let mut v = vec![1, 2, 3, 4, 5];

let first = &v[0];

v.push(6);

println!("The first element is: {first}");
```

Ye compile nahi karega.

Error:

```text
cannot borrow `v` as mutable
because it is also borrowed as immutable
```

---

## 💥 Ye Error Kyun Aaya?

Important reason sirf borrowing rule nahi, **vector ki memory layout** bhi hai.

Vector elements memory mein contiguous hote hain:

```text
[v0][v1][v2][v3][v4]
```

Ab:

```rust
let first = &v[0];
```

`first` vector ke first element ko point kar raha hai.

Phir:

```rust
v.push(6);
```

Agar current memory mein jagah nahi hui toh Rust ko:

```text
Old memory
[v0][v1][v2][v3][v4]

        ↓ reallocate

New memory
[v0][v1][v2][v3][v4][v5]
```

karna pad sakta hai.

Purane elements new memory mein copy ho sakte hain.

Toh `first` purani memory ke element ko point kar raha hota.

```text
first
  ↓
OLD memory
  X
deallocated
```

Ye invalid reference hota.

### Borrow Checker

Rust borrow checker aisi situation ko **compile time par prevent** karta hai.

```text
immutable reference
        +
mutable vector operation
        ↓
may invalidate reference
        ↓
❌ compiler error
```

> **Borrow checker tumhe potentially dangling reference banane nahi deta.**

---

## 🔁 Iterating Over a Vector

Individual indices use karne ke bajay `for` loop se elements traverse karna common hai.

### Immutable References

```rust
let v = vec![100, 32, 57];

for i in &v {
    println!("{i}");
}
```

Yahan:

```text
&v
 ↓
vector ke elements ke immutable references
```

Milte hain.

---

## ✏️ Mutable Iteration

Mutable vector ke elements ko modify karne ke liye:

```rust
let mut v = vec![100, 32, 57];

for i in &mut v {
    *i += 50;
}
```

Result:

```text
[150, 82, 107]
```

### `*i` Kyun?

`i` ek **mutable reference** hai:

```text
i
 ↓
&mut element
```

Actual value modify karne ke liye dereference operator:

```rust
*i
```

use karte hain.

So:

```rust
*i += 50;
```

means:

> `i` jis actual value ko refer kar raha hai, us value mein `50` add karo.

---

## ⚠️ Iteration ke During Vector Modify Nahi Kar Sakte

Agar:

```rust
for i in &v {
    // ...
}
```

ya:

```rust
for i in &mut v {
    // ...
}
```

vector ka reference hold ho raha hai.

Isliye loop ke andar poore vector ko structurally modify karna:

```rust
v.push(...);
v.remove(...);
```

allowed nahi hoga.

Reason:

```text
loop holds reference to vector
          +
vector ko simultaneously modify karna
          ↓
borrowing conflict
```

> **Borrow checker vector ke references ko valid rakhta hai.**

---

# 🎭 Vector mein Multiple Types?

Normally **nahi**.

```rust
let v = vec![1, "hello", 3.5];
```

❌ Ek `Vec` different unrelated types ko directly store nahi kar sakta.

Reason:

> `Vec<T>` ke saare elements ek hi `T` type ke hote hain.

Lekin ek useful solution hai:

## 🔀 Enum Use Karo

Different types ko ek vector mein rakhna ho toh enum define kar sakte ho:

```rust
enum SpreadsheetCell {
    Int(i32),
    Float(f64),
    Text(String),
}
```

Ab:

```rust
let row = vec![
    SpreadsheetCell::Int(3),
    SpreadsheetCell::Text(String::from("blue")),
    SpreadsheetCell::Float(10.12),
];
```

Ab technically vector:

```text
Vec<SpreadsheetCell>
```

hai.

Sab elements same type hain:

```text
SpreadsheetCell
```

but har variant different data hold kar sakta hai:

```text
SpreadsheetCell::Int
SpreadsheetCell::Float
SpreadsheetCell::Text
```

### Mental Model

```text
Vec<T>
  ↓
same type required

enum
  ↓
different kinds of data ko
same enum type ke variants bana do

Vec<Enum>
  ↓
different data types ek vector mein possible
```

---

## 🧠 Why Enum Works?

Rust ko compile time par pata hona chahiye ki vector mein kaunse types possible hain.

Isse Rust:

- exact memory requirements jaanta hai
- operations ke types check kar sakta hai
- `match` se exhaustive cases ensure kar sakta hai

```rust
match cell {
    SpreadsheetCell::Int(value) => { /* ... */ }
    SpreadsheetCell::Float(value) => { /* ... */ }
    SpreadsheetCell::Text(value) => { /* ... */ }
}
```

> **Enum approach tab useful hai jab allowed types ka set pehle se known ho.**

---

## ⚠️ Agar Types Pehle Se Unknown Hon?

Agar runtime par pata hi nahi ki kaunse arbitrary types aayenge, enum approach suitable nahi hai.

Aise cases mein **trait objects** use kiye ja sakte hain.

Ye concept later Rust mein cover hota hai.

---

## 🛠️ Useful `Vec` Methods

`push()` ke alawa aur bhi methods hain.

Example:

```rust
let mut v = vec![1, 2, 3];

let last = v.pop();
```

`pop()`:

> vector ka **last element remove karke return** karta hai.

```text
[1, 2, 3]
       ↓ pop()
[1, 2]
       ↓
Some(3)
```

Empty vector par `pop()`:

```text
[]
 ↓
None
```

> `Vec<T>` ke aur bhi bahut useful methods standard library API mein available hain.

---

## 🗑️ Vector Drop Hona

Vector bhi ek normal Rust value/struct ki tarah scope ke end par drop hota hai.

```rust
{
    let v = vec![1, 2, 3, 4];

    // use v
}
```

`}` par:

```text
v goes out of scope
        ↓
vector freed
        ↓
uske elements bhi dropped
```

### Example

```text
{
    let v = vec![1, 2, 3, 4];
    
    // use v
}  ← v yahan drop hota hai
```

Vector ke contents bhi cleanup hote hain.

Borrow checker ensure karta hai ki vector ke elements ke references vector ke valid lifetime ke bahar use na hon.

# 🧠 Complete Mental Model

```text
                    Vec<T>
                      │
       ┌──────────────┼──────────────┐
       │              │              │
    Create          Access        Modify
       │              │              │
  Vec::new()        v[i]          push()
  vec![...]         get()         pop()
                   │
                   ├── &T
                   └── Option<&T>

                      │
                  Iterate
                      │
               ┌──────┴──────┐
               │             │
              &v           &mut v
               │             │
            read only     modify values
```

# 🧠 Final Cheat Sheet

| Concept | Meaning |
|---|---|
| `Vec<T>` | Same type ke multiple values ki collection |
| `Vec::new()` | Empty vector |
| `vec![...]` | Initial values ke saath vector |
| `push()` | End mein element add |
| `pop()` | Last element remove + return |
| `v[i]` | Indexing, invalid index → panic |
| `v.get(i)` | `Option<&T>`, invalid index → `None` |
| `&v` | Immutable element references |
| `&mut v` | Mutable element references |
| `*i` | Mutable reference ko dereference karke value modify |
| `Vec<T>` | Normally one element type |
| `Vec<Enum>` | Enum variants ke through different data types represent kar sakta hai |
| `drop` | Scope end par vector + contents cleanup |
| Borrow checker | Invalid references ko prevent karta hai |

> **Golden Rules**
>
> `Vec<T>` → multiple values, same `T`
>
> `vec![...]` → values diye hain, type usually infer ho jayega
>
> `Vec::new()` → empty hai, type annotation ki zarurat pad sakti hai
>
> `v[i]` → invalid index par panic
>
> `v.get(i)` → invalid index par `None`
>
> `&v` → read/immutable references
>
> `&mut v` → mutable references
>
> Vector ko mutate karte waqt existing references borrow-checker ke rules follow karenge
>
> Different data types chahiye → known set ho toh enum use kar sakte ho
>
> Vector scope se bahar jaata hai → vector aur uske elements drop hote hain
