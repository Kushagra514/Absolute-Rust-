# 8.3 HASH MAPS — RUST
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 🔑 1. HASHMAP KYA HOTA HAI?

HashMap data ko **key → value** pair mein store karta hai.

Example:

    "Blue"   → 10
    "Yellow" → 50
    "Red"    → 25

Vector mein hum data ko index se access karte hain:

    vector[0]

HashMap mein hum **key** se value access karte hain:

    map.get(&key)

### 🧠 Mental Model

    Key                  Value
     ↓                      ↓
    "Blue"  ───────────→   10
    "Red"   ───────────→   25


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 🏗️ 2. HASHMAP CREATE KARNA

Sabse pehle `HashMap` ko import karna padta hai:

    use std::collections::HashMap;

Phir:

    let mut scores = HashMap::new();

Values insert:

    scores.insert(String::from("Blue"), 10);
    scores.insert(String::from("Yellow"), 50);

Result:

    Blue   → 10
    Yellow → 50

⚠️ `mut` isliye chahiye kyunki HashMap ko modify kar rahe hain.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 🔍 3. `get()` SE VALUE ACCESS KARNA

    let team_name = String::from("Blue");

    let score = scores.get(&team_name);

`get()` ka return type hota hai:

    Option<&V>

Agar key mil gayi:

    Some(&10)

Agar key nahi mili:

    None

### 💡 `&` KYUN?

`get()` value ki reference deta hai, actual value nahi.

    &10
     ↑
     Reference

Agar reference ko dereference karoge:

    *reference

to actual value access hoti hai.

    &10  → reference
    *&10 → 10


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 📦 4. `copied()` + `unwrap_or()`

    let score = scores.get(&team_name)
        .copied()
        .unwrap_or(0);

### `copied()`

`get()` deta hai:

    Option<&i32>

`copied()`:

    Option<&i32>
          ↓
    Option<i32>

Kyunki `i32` `Copy` type hai.

### `unwrap_or(0)`

    Some(10) → 10
    None     → 0

So poora code:

    "Key ki value de,
     nahi mili toh 0 de."


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 🔐 5. HASHMAP + OWNERSHIP

Agar `String` ko HashMap mein insert karte ho:

    let field_name = String::from("Favorite color");
    let field_value = String::from("Blue");

    let mut map = HashMap::new();

    map.insert(field_name, field_value);

Ownership move ho sakti hai:

    field_name
         ↓ move
      HashMap

    field_value
         ↓ move
      HashMap

Iske baad:

    println!("{field_name}");

❌ valid nahi hoga.

### 🧠 Basic Rule

    Copy types → copy
    String     → move


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 🔗 6. HASHMAP MEIN REFERENCE STORE KARNA

Agar:

    map.insert(key, &value);

to actual value HashMap mein move nahi hoti.

HashMap ke andar **reference** store hota hai:

    value
    ┌───────┐
    │  10   │
    └───────┘
        ↑
        │ reference
        │
    HashMap
    ┌──────────────┐
    │ key → &value │
    └──────────────┘

Iska matlab:

    &value

actual value nahi hai.

Ye value ko point karne wala reference hai.

Dereference:

    *reference

actual value tak pahunchta hai.

⚠️ Reference jis value ko point kar raha hai,
woh HashMap ke valid rehne tak valid rehni chahiye.

Ye concept **lifetimes** se related hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 🔄 7. SAME KEY DOBARA INSERT KARNA

    scores.insert(String::from("Blue"), 10);
    scores.insert(String::from("Blue"), 25);

Pehle:

    Blue → 10

Doosre `insert()` ke baad:

    Blue → 25

### ⚠️ Important

Same key ki purani value **overwrite** ho jaati hai.

    insert()
       ↓
    same key?
       ↓
      YES
       ↓
    old value replace

## 🚪 8. `entry()` + `or_insert()`

Kabhi hume chahiye:

> "Agar key nahi hai tab insert karo,
> lekin agar already hai toh purani value ko mat badlo."

Iske liye:

    map.entry(key).or_insert(value);

Example:

    scores.entry(String::from("Yellow")).or_insert(50);
    scores.entry(String::from("Blue")).or_insert(50);

Agar pehle:

    Blue → 10

hai, final:

    Blue   → 10
    Yellow → 50

`Blue → 10` ko `50` se replace nahi kiya.

### 🧠 Simple Logic

    entry(key)
        ↓
    key exists?
       / \
     YES  NO
      ↓    ↓
    keep  insert


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ⭐ 9. SABSE IMPORTANT DOUBT:
# `or_insert()` MUTABLE REFERENCE KYUN RETURN KARTA HAI?

Code:

    let count = map.entry(word).or_insert(0);
    *count += 1;

Yahan main point hai:

> Hume value ki **copy** nahi chahiye.
> Hume HashMap ke andar stored **original value ko modify** karna hai.

Suppose:

    HashMap:
    "world" → 1

Agar `or_insert()` sirf `1` return karta:

    HashMap:
    "world" → 1

    count:
    1  ← COPY

Phir:

    count += 1;

Result:

    HashMap:
    "world" → 1

    count:
    2

❌ HashMap ki value change hi nahi hui.

Hume chahiye:

    HashMap:
    "world" → 2

Isliye `or_insert()` actual stored value ka:

    &mut i32

return karta hai.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 🎯 10. `&mut` KA ACTUAL MEANING

Suppose:

    HashMap:
    "world" → 1
                  ↑
                &mut
                  ↑
               count

`count` actual `1` nahi hai.

`count` ke paas **HashMap ke andar stored `1` ko modify karne ka access** hai.

So:

    let count = map.entry(word).or_insert(0);

roughly:

    count: &mut i32

Then:

    *count += 1;

means:

> `count` jis actual value ko point kar raha hai,
> us actual value ko 1 se increase karo.

Result:

    "world" → 1

        ↓ *count += 1

    "world" → 2


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## ❓ 11. "LEKIN `i32` TOH COPY HO SAKTA HAI?"

Exactly.

`i32` ka `Copy` hona problem nahi hai.

Lekin **Copy aur mutable reference ka purpose alag hai.**

### Copy

    value → copy

Meaning:

> Value ki ek separate copy mil gayi.

### `&mut`

    &mut value

Meaning:

> Original stored value ko modify karne ka access mil gaya.


### Compare:

    Returning i32:

    HashMap → 1
    count   → 1  ← copy

    count += 1

    HashMap → 1
    count   → 2


    Returning &mut i32:

    HashMap → 1
                 ↑
               count

    *count += 1

    HashMap → 2


🔥 **CORE IDEA:**

    Copy
    = value ki COPY

    &mut
    = ORIGINAL value ko MODIFY karne ka access


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## ⭐ 12. `*count` MEIN `*` KYUN?

    let count = map.entry(word).or_insert(0);

Yahan:

    count: &mut i32

Matlab:

    count
      │
      │ points to
      ↓
    ┌─────┐
    │  1  │
    └─────┘
      ↑
      │
    HashMap ki actual value

`count` = reference

`*count` = actual value

Therefore:

    *count += 1;

means:

    Actual HashMap value += 1


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 📝 13. WORD COUNT EXAMPLE

    let text = "hello world wonderful world";

    let mut map = HashMap::new();

    for word in text.split_whitespace() {
        let count = map.entry(word).or_insert(0);
        *count += 1;
    }

### Step-by-step:

    "hello"
        ↓
    hello → 0
        ↓
    *count += 1
        ↓
    hello → 1


    "world"
        ↓
    world → 0
        ↓
    *count += 1
        ↓
    world → 1


    "wonderful"
        ↓
    wonderful → 0
        ↓
    *count += 1
        ↓
    wonderful → 1


    "world" again
        ↓
    world already exists
        ↓
    or_insert(0) does NOT replace 1 with 0
        ↓
    existing value = 1
        ↓
    *count += 1
        ↓
    world → 2


Final:

    hello     → 1
    world     → 2
    wonderful → 1

    text.split_whitespace()

    "hello world wonderful world"

    "hello"

# 🧠 FINAL MENTAL MODEL

HashMap:

    Key → Value

`get()`:

    Key
     ↓
    Option<&Value>

`insert()`:

    key + value
         ↓
    same key ho toh overwrite

`entry().or_insert()`:

    key
     ↓
    ┌─────────────────┐
    │ key exists?     │
    └─────────────────┘
       ↓           ↓
      YES          NO
       ↓           ↓
    existing     insert
     value       default
       ↓           ↓
       └─────┬─────┘
             ↓
          &mut Value

Why `&mut Value`?

    ❌ Copy return karoge
       → sirf copy modify hogi

    ✅ &mut return karoge
       → HashMap ke andar original value modify hogi

Therefore:

    let count = map.entry(word).or_insert(0);
    *count += 1;

means:

    "Word ki entry lao.
     Nahi hai toh 0 se create karo.
     Us actual stored number ka mutable reference do.
     Phir usi number ko 1 se increase karo."

## ⚡ ONE-LINE REVISION

`or_insert()` **`&mut V` isliye return karta hai kyunki hume HashMap mein stored actual value ko modify karna hota hai; `i32` ka `Copy` hona sirf value ki copy banane ki ability deta hai, original HashMap value ko modify nahi karta.**
